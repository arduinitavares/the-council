# Dispatch Seats and the Judge via T3 MCP

_Supersedes ADR-0004's outbound dispatch decision (direct CLI dispatch over MCP/UTCP) and updates ADR-0002 (Orca is retired in favor of T3). Retains ADR-0004's `bin/council` inbound CLI and pure `VisualizerLiveWatcher` observer architecture._

We originally chose `node:child_process.execFile` behind `HarnessAdapter` (`executeSeat`, `executeJudge`) in ADR-0004 because `codex` (`--json`), `agy` (`json`), and `cursor-agent` (`stream-json`) were standalone local CLIs and T3 did not yet exist. Maintaining direct subprocess orchestration, divergent output parsers, POSIX process-group drain custody, and nested error-redaction logic recreated the same complexity ADR-0002 rejected when replacing `src/pilot/` (~`66,000` lines of harness/runner code on `fix/issue-107-agy-stream-json` vs. `9,586` lines in `src/harness/*.js` on `main`).

T3 now exposes a single Streamable HTTP MCP control plane (`http://127.0.0.1:3773/mcp`) covering `codex`, `antigravity`, and `cursor` via `orchestrator_capabilities`, `t3_thread_launch`, `t3_thread_wait`, `t3_thread_read`, `t3_thread_interrupt`, and `t3_thread_organize`. On `feat/t3-mcp-harness`, we therefore introduce `T3HarnessAdapter` and a zero-dependency Streamable HTTP `T3McpClient` (Node >= 22 global `fetch`) behind an explicit `--backend t3|cli` selector (with `cli` remaining default until live parity is proven):

- **Fresh thread per attempt:** Each Seat, Judge, or recovery retry dispatches a fresh T3 thread (`t3_thread_launch` with a nonempty `title`, `<= 120,000`-char formatted message, and attempt-scoped `clientRequestId`) because `CouncilEngine` shifts `tools`, `cwd`, `model`, and `reasoningEffort` across Clarification Batches, Deliberation Rounds, Voting, Rebuttal, and Retries (`t3_thread_send` cannot alter workspace, modes, or model). Threads are archived via `t3_thread_organize` only when confirmed terminal, leaving unconfirmed threads visible in T3 UI.
- **Bounded run-scoped lifecycle:** Attempts resolve `runId` from launch (or one bounded `t3_thread_read` `latestRunId` check), await explicit `runId` slices via `t3_thread_wait`, detect stalled interactive prompts via `thread.pendingRequestCount` (`HeadlessToolDeniedError`), require `timedOut === false && status === 'completed'` before paging `messages` forward to `hasMore === false` (plus `itemId`/`textOffset` reassembly) and reading `activity`, reuse the active telemetry gate via `getActiveAttemptTelemetryGate()`, and cancel on timeout or `AbortSignal` via run-scoped `t3_thread_interrupt({ threadId, runId })` (omitting `stop: true`) under a fresh `1,000–2,000 ms` cleanup signal.
- **Honest T3 trust boundary:** T3 MCP does not expose OS-level per-turn tool-disable flags or `.council/` path exclusions (and Codex `runtimeMode: "auto"` relies on `interactionMode: "plan"` for read-only posture). Under `--backend t3`, T3 owns execution sandboxing and permissions (`scratch: true` + `interactionMode: "plan"` + `runtimeMode: "auto"` for `tools: "none"` or absent `cwd`; resolved `projectId` + `workspaceStrategy: { type: "root" }` + `interactionMode: "plan"` + `runtimeMode: "auto"` for explicit `cwd`), paired with best-effort post-turn `view: "activity"` `.council/` inspection. Users needing strict OS-level `read-only` sandboxing or `.council/` filtered-copy isolation stay on `--backend cli` during coexistence.
- **Credential boundary & coexistence:** Loopback `http://127.0.0.1:3773/mcp` rejects anonymous requests with `401 invalid_mcp_credential`, so `T3McpClient` accepts configured credentials (`T3_MCP_URL`, `T3_MCP_TOKEN`) or an injected caller without scraping private client stores, sends `Accept: application/json, text/event-stream` on every `POST`, forwards `Mcp-Session-Id` onto `notifications/initialized`, and strips `T3_MCP_TOKEN` from legacy CLI subprocesses (`buildSanitizedCliEnv`, `listAntigravityModels`). CLI `--backend t3` preflights `healthCheck()` + `orchestrator_capabilities` before `CouncilEngine.run()` and passes descriptors into `recovery.js` so `--retry-effort-fallback` never invokes `agy models`; shared model/telemetry utilities are extracted from `cli-runner.js` while keeping `--backend cli` rollback and leaving `fix/issue-107-agy-stream-json` untouched until live parity is verified.
- **Unchanged core:** `CouncilEngine` (including the `EXCUSE_SEAT` reducer), Clarification Batch and Deliberation Round transitions, Proof admission, Candidate synthesis, Objection preservation, `bin/council`, and `VisualizerLiveWatcher` telemetry remain unchanged behind `HarnessAdapter`.
