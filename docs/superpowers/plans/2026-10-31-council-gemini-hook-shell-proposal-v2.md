# Scoped Gemini hook environment proposal

This is revision 2 for independent re-review. The original proposal remains immutable. No experiment or production edit is approved by this document alone.

**Goal:** Remove the known Orca hook's dynamic endpoint dependency without changing global hooks, permissions, settings, or Cursor.

**Evidence:** The installed AGY binary constructs command hooks with `sh -c`, resolved through PATH. It copies its process environment and adds a conversation ID. The exact known Orca script uses environment-selected endpoint sourcing and invokes Python before checking endpoint state. Parent environment filtering does not enforce the environment at that actual shell boundary.

**Proposed repair:** Generate a source-bound, launch-scoped `sh` adapter in the Council packet profile. Put only its task-owned directory before the original PATH for this AGY process. The adapter recognizes the exact five reviewed Orca command descriptors separately from script integrity. Every recognized command, or command that refers to the known Orca hook path, is prohibited from unfiltered delegation. A recognized command enters a clean environment first. A small source-bound Node verifier then checks the original script identity, bytes and metadata. It runs a profile copy of those exact verified script bytes through the equivalent reviewed descriptor template. The known script does not use its own path or $0. This removes the original-path change window. Integrity failure exits nonzero and never falls through. A command that refers to the hook path but does not match an exact descriptor exits nonzero. Only unrelated commands delegate to absolute `/bin/sh` with their normal environment. It does not fabricate hook decisions, suppress the original script, modify Deny rules, or change global files. Unknown hook variants retain existing unavailable guards.

**Adapter bootstrap:** On this inspected macOS host, `/bin/sh` is Bash 3.2.57. A script interpreter line `#!/bin/sh -p` prevents ENV/BASH_ENV startup processing, inherited shell functions and SHELLOPTS before the adapter can clear the child environment. The local primary manual at `/usr/share/man/man1/bash.1` documents this behavior. Require equal real/effective user and group IDs. The option does not grant OS access or change IDs in that case. Reject unsupported platforms or shell contracts rather than adding a fallback. A direct native helper is an alternative only if this bootstrap cannot be qualified; do not invent a permission bypass.

**Known-command environment:** Use only shell builtins before absolute `/usr/bin/env -i`. Change cwd with a builtin, then exec the clean verifier using the exact source-bound Node executable already used by Council. The verifier uses builtin Node modules only. Use a strictly empty cwd/HOME root at mode 0o500. Use a separate per-run temporary scratch root at mode 0o700 for expected system-helper cache writes. Set PATH=/usr/bin:/bin, PYTHONNOUSERSITE=1, PYTHONDONTWRITEBYTECODE=1, LC_ALL=C and LANG=C. The matched path must not recurse through the adapter PATH. No ORCA variable, ENV, BASH_ENV, PYTHONPATH or PYTHONHOME reaches the original command. The system Python runtime and possible Command Line Tools temporary caches are explicit platform effects. Record the resolved system helper/runtime identities. Qualification must reject an unexpected user-writable startup source. Do not claim mode 0o500 contains every filesystem effect or that xcrun necessarily tolerates a denied cache write. A read-only TMPDIR test can inform the result, but is not a prerequisite or a reason to bypass a denial. Inspect the actual scratch changes and retain their limits. Do not claim an unverified Python flag disables startup. The known script therefore cannot source the endpoint, send HTTP, or write a spool record, independent of ORCA variables that AGY may add before its shell call. The original permission response remains unchanged.

**Required integrity:** Reuse the existing materializations pipeline, extended with explicit modes and AGY profile checks. Bind the generated sh adapter at exact mode 0o500, its source-bound verifier and copied script, and parent directory identity. Check lstat, regular/non-symlink type, effective-user ownership, exact byte digests and execute access even on EEXIST. An adapter at 0o600 must refuse the whole launch before Go can skip it and find /bin/sh. Require empty cwd/HOME roots at mode 0o500; keep temporary scratch separate. Reject missing files, invalid roots and source drift. Bind the launch PATH, profile and materializations in recipeHash and the wrapper assignment. Normalize PATH to nonempty absolute segments; reject relative or empty entries for this profile. Pin the inspected AGY binary digest 34423fc9b0af3841e7646aa72a2d40ffeab8218b22d1cb99eac7355f9eba31e3. Track /bin/sh, /usr/bin/env, the Node executable, original hook bytes and hook metadata. Reject unsupported identities rather than extending a version-only contract. Keep all writes under .council/native-packets and task-owned tests. Do not inherit this contract for arbitrary shell commands, hook scripts or future provider layouts. Keep effective stream initialization and provider runtime qualification separate.

**Proposed file scope:** A new focused src/pilot/agy-hook-shell.ts module; src/pilot/provider-controls.ts for exact hook recognition and audited effect construction; src/pilot/provider-session.ts for profile materialization and launch PATH; src/pilot/wrapper-contract.ts for a strict optional AGY-only profile field. Add focused tests in test/pilot/agy-hook-shell.test.ts and extend the existing provider-controls/provider-session tests. The profile may have a strict optional AGY-only field; it must not duplicate materialization logic. Apply recognition only to selection.route === antigravity. Preserve Cursor and all other route behavior. Exact interfaces remain provisional until review and the disposable experiment pass. Do not change Cursor code or permissions.
