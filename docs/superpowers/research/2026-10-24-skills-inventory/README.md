## Recommended hybrid rule

Use the local inventory to propose a small topic profile. No source or profile in this inventory is admitted to the future runtime yet. All seats can later receive the same reviewed supplied-text methods and output requirements. Each seat chooses within that admitted set and records its choice.

A new skill request is data for the coordinator. Selection never adds permissions, helpers, interviews, external writes, or uncounted model calls. Bind the selected source paths, hashes, adaptations, and profile revision to the round packet.

Distinguish methods from full workflows. Every adaptation must list original requirements retained, replaced, and excluded, plus the reason. Pin the entry file and the complete required companion/script bundle before admission. The current JSON hashes direct relative Markdown companions only and records its incomplete closure. Do not claim the original workflow ran unchanged.

Discovery rule: a seat reports a specific missing capability and why the admitted local set cannot address it. The coordinator checks the local inventory first, then can use find-skills for bounded read-only ecosystem discovery. The user retains installation and persistent-change authority. Installation commands, including -g -y, are outside a Council run. New method sources enter only a reviewed later profile/round revision.

Keep authoring provenance separate from native provider exposure. The mapping author is OpenAI. The independent assessor is fresh Claude Sonnet High through Orca. AGY does not inherit the Codex plugin catalog.

## Findings that affect selection

1. **28 files contain affiliate/footer requirements.** The Software Architect package is excluded from automatic loading. Useful concepts require separate review and explicit adaptation.
2. **34 files set `disable-model-invocation: true`.** They are inventory entries, not permission for automatic activation.
3. **26 files match explicit disabled-skill names in local Codex configuration.** Pages skills are also disabled for this chat. Preserve both restrictions.
4. **Nested workflows conflict with ordinary reviewer scope.** research creates a background agent, code-review creates two subagents, and improve-codebase-architecture combines exploration, HTML output, interviews, and documentation changes.
5. **Some routers assume other installed flows.** ask-matt maps its own engineering suite and is explicit-only. It is not a whole-inventory registry. bounded-codebase-investigation references scoped-code-review and preimplementation-review, neither found in this scan. These are unresolved references, not permission to invent replacements.
6. **Regex flags need human interpretation.** For example, “Do not modify files” and “push back” can trigger a word-based write flag. The inventory retains matching lines for inspection, not as proof of effects.
7. **Refocusing is OpenRig-specific.** Its full source requires topology/work trace and rig configuration. It is conditional coordinator support, not a generic argument-review or resume step.
8. **Do not spread a disabled flag to an entire package.** pstack-plugin:unslop is not explicitly disabled, even though other pstack entries are. Check the exact source. All profiles remain proposed and must be admitted separately.
9. **Specialist gaps remain explicit.** Non-promotional security, reliability, scalability, and API-design methods have not been admitted. The agent-skills cache contains possible sources, including doubt-driven-development and source-driven-development, but cache presence is not qualified availability.
10. **Memory and history are not neutral seat inputs.** The coordinator selects topic-relevant, authorized evidence for the common handoff. Reviewers and judges do not independently pull private histories or other seats' conversations through MemPalace or Chronicle. A shared evidence pack preserves independence.

## Should the Council just use find-skills?

No automatic ecosystem search is needed for the core profiles above. The installed find-skills file describes searching skills.sh and installing packages. It does not inventory local installations or evaluate their workflow compatibility.

Use it when a concrete required capability is missing from the local map. Inspect the candidate source and action requirements before recommending it. Popularity and repository reputation are signals, not proof of suitability.

Discovery does not authorize installation. Any new source must enter a later reviewed profile revision. It cannot silently change a running round. No ecosystem search or installation was performed for this inventory.
