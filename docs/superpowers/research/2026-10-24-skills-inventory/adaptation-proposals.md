# Proposed Council method adaptations

These are adaptation proposals for design review, not runnable skills or admitted runtime profiles. Original workflows remain unchanged.

Each admitted version must pin source entry and complete required companion/script hashes. The inventory records direct companion links only.

| Activity | Retained method | Replaced by Council control | Excluded from a reviewer seat |
| --- | --- | --- | --- |
| Clarify a problem or decision | Problem, priorities, constraints, one-question discovery, and the original stop conditions. | Human questions move to the coordinator before admission or to shared missing-input IDs. | Private user interviews by reviewers and premature solution proposals under define-the-problem. |
| Research facts and compare options | Primary-source claims, contrary evidence, locations, revision/retrieval time, and explicit uncertainty. | The coordinator/evidence adapter retrieves and records the evidence. | Worker-created research agents, unrestricted browsing, and worker repository writes. |
| Understand existing software | Bounded path map, exact revision, evidence locations, read-only reasoning, and safe-shell pairing where commands are used. | The adapter performs approved commands and supplies current artifacts. | Silent indexing, dashboards, missing-helper substitution, and broad worker filesystem access. |
| Choose or challenge an architecture | Deep-module vocabulary, domain scenarios, alternatives, assumptions, tradeoffs, and source-based friction. | Coordinator-owned context requests and separately approved documentation. | improve-codebase-architecture auto-invocation, helper spawning, interactive grilling, and glossary/HTML writes by seats. |
| Review a code change | Pinned comparison, originating requirements, Standards/Spec separation, actionable defects, and real evidence. | Missing fixed point/spec is a shared missing-input request. Any approved review dispatch stays with the coordinator through Orca. | Tracker setup, nested Standards/Spec agents within each seat, commits, publishing, or source fixes. |
| Diagnose a failure or regression | Reproduction evidence before diagnosis, ranked falsifiable hypotheses, decisive checks, and redacted evidence. | The adapter runs bounded checks. Missing reproduction evidence remains unresolved instead of a guessed diagnosis. | Worker instrumentation, source changes, fixes, and regression-test implementation. |
| Check evidence and proposed validation | Fresh inspected evidence, actual versus proposed checks, exact commands/revisions, and meaningful failure cases. | Approved checks run through the adapter. GCP actions require auth verification and applicable resource attribution. | Treating a test proposal as a passing test, or treating TDD as authority to implement. |
| Challenge arguments and receive feedback | Read, understand, verify, evaluate, and explicitly accept or challenge each material claim. Stop unsupported decisions when inputs are unclear. | Ambiguity becomes a shared unresolved issue or missing-input ID. | Automatic implementation of feedback, private interviews, and changing consensus to majority/ruling authority. |
| Assess a plan and its dependencies | Coverage, dependencies, named interfaces, readiness, scope, validation, and explicit assumptions. | The coordinator owns authoring and the selected Superpowers flow. | Worker ticket creation, tracker updates, execution, or substituting another outer development methodology. |
| Decide from data or metrics | Relevant context, data quality, reproducibility, limitations, and observed calculations. | Authenticated retrieval and calculation are separately scoped adapter tasks. | General admission of the specialist pack without source/dependency review or authority to change datasets. |
| Explain a decision and its uncertainty | Issue 9-oriented structure, protected technical literals, exact uncertainty, and consistent terms. | The coordinator renders diagrams and documents. Conflicting style rules stay subordinate to preserved meaning and the Council contract. | ASD certification claims, promotion, external publication, or changes to technical facts for style. |
| Coordinate workers and preserve scope | Current host policy, explicit model/effort, scope, ownership, denial stops, settlement evidence, handoff, and source provenance. | Only the coordinator owns Orca placement, slots, lifecycle, and writes. | Independent worker helpers, invented lifecycle IDs, or grants inferred from a skill. |
| Discover or maintain skills | Local search first, a concrete capability gap, source inspection, and explicit provenance. | The coordinator assesses a request and can run bounded ecosystem discovery. The user retains installation/persistent-change authority. | Automatic installation, updates, repairs, registry churn during a round, or activation of disabled/explicit-only originals. |
| Add topic-specific expertise | Only topic-relevant domain checks that have been inspected and supported by current evidence. | Each candidate needs a separate scoped source/dependency and output-contract review before admission. | Wholesale plugin activation, inherited Codex exposure in AGY, promotional requirements, or claiming expertise from an artifact template. |
