### Concrete Defects and Smallest Fixes

#### Defect 1: `preflight -> settling` guard in `states` is not mutually exclusive with `preflight -> publishing_answers` or `preflight -> collecting_questions`, and misses open unfinalized non-blocking question batches
- **Exact locations:**
  - [the-council.json](file:///Users/aaat/projects/the-council/docs/superpowers/diagrams/the-council.json) (`states` transitions `preflight -> publishing_answers`, `preflight -> collecting_questions`, `preflight -> prepare_round`, `preflight -> clarifying`, and `preflight -> settling`)
  - [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L305-L323) and [#L629](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L629)
  - [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L211) and [#L378](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L378)
- **Counterexamples:**
  1. **`AnswerRevision` at `CLARIFICATION_LIMIT` or `AnswerBatch` at Round 3:** Suppose batch 2 of 2 settles to `needs_user` (`CLARIFICATION_LIMIT`) with an unresolved blocking question `q1`, and the user queues a valid [`AnswerRevision`](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L124) and runs `resume`. On entering `preflight`, `q1` is still unresolved in `questionLedger` until `publishing_answers` commits the revision, and no clarification continuation remains (`clarificationBatchesUsed === effective.maxClarificationBatches`). Both `preflight -> publishing_answers` (`"checks pass; finalized queued AnswerBatch OR valid current-hash AnswerRevision"`) and `preflight -> settling` (`"blocking ledger item with no allowed clarification continuation OR effective round limit; pending needs_user"`) evaluate true simultaneously. The same collision occurs when resuming with a finalized `AnswerBatch` for a deliberation question in rounds 1–3 (where no clarification continuation is allowed, and in round 3 `effective round limit` is also true).
  2. **Round 3 `ContextUpdate` with staged `missingInputQuestions`:** In round 3 (`roundsUsed === effective.maxRounds`), if a barrier has both staged `missingInputQuestions` and an accepted pending `ContextUpdate`, it routes to `preflight` with `saved batch collection target`. In `preflight`, both `preflight -> collecting_questions` (`"checks pass; saved batch collection target"`) and `preflight -> settling` (`"... OR effective round limit; pending needs_user"`) are simultaneously true.
  3. **Budget-only `BoundedExtension` while a non-blocking `QuestionBatch` is open:** Under [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L317), even a non-blocking `missingInputQuestions` entry diverts the round, freezes a `QuestionBatch`, and pauses at `needs_user`. If the user submits only an active-budget `BoundedExtension` (without finalizing the `AnswerBatch`) and runs `resume` in round 1 (`roundsUsed < effective.maxRounds`) with no blocking item in the ledger, `preflight -> settling` is false because neither `"blocking ledger item..."` nor `"effective round limit"` holds, allowing `preflight -> prepare_round` (or `preflight -> clarifying` in wave 1) to bypass the unfinalized question batch.
- **Smallest fix:**
  - Guard `preflight -> settling` so it applies only when there is **no** finalized queued `AnswerBatch`/valid `AnswerRevision` and **no** saved `collecting_questions` target, and include an **open unfinalized `QuestionBatch`**:
    `"no finalized AnswerBatch or valid AnswerRevision; no saved batch-collection target; (open unfinalized QuestionBatch OR blocking ledger item with no allowed clarification continuation OR effective round limit); pending needs_user"`
  - Explicitly require `"no open unfinalized QuestionBatch"` on `preflight -> clarifying` and `preflight -> prepare_round`.

#### Defect 2: Non-final all-ready clarification wave with an earlier unresolved blocking ledger item has no enabled outgoing guard from `publishing_answers`
- **Exact locations:**
  - [the-council.json](file:///Users/aaat/projects/the-council/docs/superpowers/diagrams/the-council.json) (`states` transitions from `publishing_answers`, and `clarification` edge `ready -> limit`)
  - [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L297-L307)
  - [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L210-L211) and [#L378](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L378)
- **Counterexample:**
  - Authorize `effective.maxClarificationBatches = 3`. In wave 1 (`used = 1`), seat 1 asks blocking question `q1`, which is finalized as `unknown`. Wave 1 publishes and admits wave 2 (`used = 2 < 3`).
  - In wave 2 (`used = 2 < 3`), all three seats return readiness (`all-ready wave`, zero questions). Wave 2 proceeds `clarifying -> collecting_questions -> publishing_answers`.
  - In `publishing_answers`:
    1. `publishing_answers -> clarifying` is false because `current wave had questions` is false (and launching wave 3 after all seats returned readiness would violate the no-readiness-wave rule).
    2. `publishing_answers -> prepare_round` is false because `q1` is an unresolved blocking ledger item.
    3. `publishing_answers -> settling` (`"(unresolved blocking ledger item after final clarification, deliberation, or answer revision) OR (roundsUsed >= effective.maxRounds)"`) is **also false** because wave 2 (`used = 2 < 3`) is not `final clarification`, `deliberation`, or `answer revision`, and `roundsUsed = 0 < effective.maxRounds`.
  - Additionally, when `collecting_questions -> publishing_answers` fires on `"source answers complete; no human answers needed"`, if wave 1 had only source-answered questions (no human `AnswerBatch`), `publishing_answers -> clarifying` requires `"answer_batch only"`, while an all-ready wave passing through `publishing_answers` must not mint a new `contextHash` that would invalidate a queued `ContextUpdate`.
- **Smallest fix:**
  - In [the-council.json](file:///Users/aaat/projects/the-council/docs/superpowers/diagrams/the-council.json), update `publishing_answers -> settling` to include `all-ready wave`:
    `"(unresolved blocking ledger item after all-ready wave, final clarification, deliberation, or answer revision) OR (roundsUsed >= effective.maxRounds)"`, and in the `clarification` flowchart change `ready -> limit` from `"earlier blocking answer still unresolved at final wave"` to `"earlier blocking answer still unresolved"`.
  - Specify in [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L307) and [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L378) that `collecting_questions -> publishing_answers` records `publicationKind = 'answer_batch'` when publishing source-answered batches, and preserves `contextRevision`/`contextHash` when an all-ready wave adds no questions or answers.

#### Defect 3: `reconcileOriginState` capture on in-machine transitions and premature `resumeTarget` clearing before `publishing_answers`
- **Exact locations:**
  - [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L196)
  - [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L307) and [#L497-L499](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L497-L499)
  - [the-council.json](file:///Users/aaat/projects/the-council/docs/superpowers/diagrams/the-council.json) (`reconciling -> preflight` and `publishing_answers -> prepare_round`)
- **Counterexamples:**
  1. **Premature `resumeTarget` clearing on `preflight -> publishing_answers`:** [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L196) says `"clear a consumed resumeTarget after preflight"`. When resuming from `needs_user` with a valid [`AnswerRevision`](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L124), `reconciling -> preflight` checks that a saved target exists, and `preflight` transitions to `publishing_answers`. If `preflight` clears `resumeTarget` on exit, then `publishing_answers -> prepare_round` (`"... OR answer_revision saved target"`, [2026-10-23-the-council-design.md](file:///Users/aaat/projects/the-council/docs/superpowers/specs/2026-10-23-the-council-design.md#L307)) has no saved target when `publishing_answers` finishes. Likewise, transitions into `settling` for `needs_user` at `CLARIFICATION_LIMIT`, unresolved deliberation questions, or `ROUND_LIMIT` must explicitly record `resumeTarget = 'prepare_round'` so later `AnswerRevision` or `BoundedExtension` resumes have that target.
  2. **In-machine transitions into `reconciling`:** [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L196) specifies that `restoreForReconciliation` sets `reconcileOriginState`, but `reduceRun` also has direct transitions into `reconciling` from `needs_user`, `needs_context`, `blocked`, `settling`, and active phases. If those reducer transitions do not also set `reconcileOriginState = snapshot.state` (preserving it on `reconciling -> reconciling`), `reconcileOriginState` is `null` and triggers the missing-origin blocker.
- **Smallest fix:**
  - In [2026-10-23-the-council-implementation-plan.md](file:///Users/aaat/projects/the-council/docs/superpowers/plans/2026-10-23-the-council-implementation-plan.md#L196), specify that **both** `restoreForReconciliation` and any reducer transition entering `reconciling` from a non-`reconciling` state record `reconcileOriginState = priorState`, that transitions to `settling` with `pendingOutcome = 'needs_user'` at clarification/round/question limits record `resumeTarget = 'prepare_round'` (and `collecting_questions -> settling` records `'publishing_answers'`), and that `resumeTarget` is cleared only when the transition into that target phase commits (including `publishing_answers -> prepare_round`), not when `preflight` diverts through `publishing_answers`.
